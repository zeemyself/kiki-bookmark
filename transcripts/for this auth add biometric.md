### Why It Was Getting Stuck in the Lock Overlay

In mobile operating systems (iOS and Android), presenting any native system dialog—including the **Face ID / Touch ID system prompt** or alerts—temporarily transitions the application state to `'inactive'`.

When the biometric check succeeded and the system dialog dismissed, the app transitioned back from `'inactive'` $\rightarrow$ `'active'`. The previous `AppState` listener was treating every `'inactive'` $\rightarrow$ `'active'` transition as an **App Resume from Background**, which immediately re-locked the screen and triggered an infinite lock loop.

---

### What Was Fixed

1. **True Background State Tracking (`wasBackgroundedRef`)**:
   - The lock guard now only flags the app as backgrounded when `AppState` explicitly transitions to `'background'` (i.e. when the user actually switches apps, presses Home, or locks the device).
   - Transient `'inactive'` states caused by system sheets, keyboard popups, in-app alerts, or the biometric dialog itself are safely ignored.

2. **Automatic Loop Dismissal**:
   - When `authenticateWithBiometrics()` succeeds, `isLocked` is immediately set to `false` and `wasBackgroundedRef` is cleared so you can continue using the app without interruption.

3. **Cold Boot Guard**:
   - On initial launch, it only engages the lock if the user is currently logged in, has biometrics enrolled on the device, and has the setting explicitly enabled.
