I have resolved the issue where creating new bookmarks or collections was not working after logging in with Auth0.

### Cause of the Issue
When authenticated with Auth0, items were correctly created in SQLite with the Auth0 user's ID (`ownerId: user.sub`). However, `getBookmarks` and `getCollections` in [`HomeScreen.tsx`](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/HomeScreen.tsx), [`CollectionDetailsScreen.tsx`](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/CollectionDetailsScreen.tsx), and [`BookmarkDetailsScreen.tsx`](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/BookmarkDetailsScreen.tsx) were called without passing `ownerId`. These repository methods defaulted `ownerId` to the fallback mock user `usr_kiki_01` (`CURRENT_USER.id`), filtering out the newly created bookmarks and collections from the UI and modal selectors.

### Summary of Fixes
1. **[HomeScreen.tsx](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/HomeScreen.tsx)**:
   - Passed `ownerId: activeUserId` to `getBookmarks` and `getCollections` in `loadData()`.
   - Ensured the Auth0 user profile is automatically upserted into SQLite `users` upon login to satisfy foreign key constraints and synchronize profile claims.
2. **[CollectionDetailsScreen.tsx](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/CollectionDetailsScreen.tsx)**:
   - Integrated `useAuth0` to obtain `activeUserId`.
   - Passed `ownerId: activeUserId` to `getBookmarks`, `getCollections`, and `createBookmark`.
3. **[BookmarkDetailsScreen.tsx](file:///Users/zeemyself/Projects/kiki-bookmark/src/screens/BookmarkDetailsScreen.tsx)**:
   - Integrated `useAuth0` to obtain `activeUserId`.
   - Passed `ownerId: activeUserId` to `getCollections` so edit modals load the user's collections.

For full details, please refer to the [Walkthrough document](file:///Users/zeemyself/.gemini/antigravity-ide/brain/29dd7510-e7b7-4dbe-8ca3-6ec8e68781c7/walkthrough.md).
